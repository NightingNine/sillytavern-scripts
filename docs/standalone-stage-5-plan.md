# 独立版迁移阶段 5 计划：发布交付闭环

## 范围

- 只修改独立版分支 `feature/auto-card-studio-standalone`，脚本版继续冻结。
- 发布页允许勾选每项产物当前选中的版本，并保存角色名、世界书名、创作者、输出语言、人称及可选 PNG 头像。
- 隐藏重组步骤只读取本次勾选的正式产物，不读取附属世界书，不写入普通步骤对话。
- 模型输出只是候选方案：必须通过 blockId 唯一覆盖、类型、动作、条目属性和位置校验；失败自动修正一次，再以本地安全分组补齐，任何已选产物不得静默遗漏。

## 交付契约

- 始终生成 `角色名.character.json`、`角色名.worldbook.json`、`角色名.regex.json`、`角色名-创作档案.md`。
- 仅当头像是结构有效的 PNG 时生成 `角色名.png`；写入 SillyTavern 1.18.0 使用的 `chara` 与 `ccv3` 文本块。
- 角色卡使用 `chara_card_v3`，内嵌世界书使用 `data.character_book.entries` 数组，独立世界书使用 `entries` 对象且对象键严格等于字符串化 `uid`。
- Step 23 的 HTML 与捕获表达式组合成“🕹️显示状态栏”；用户可选是否附加 Step 24 的九条通用局部正则。
- ZIP 在内存中完整构建并重新解析校验；覆盖、JSON 或 PNG 校验失败时不返回半成品。

## 最少实现结构

- 新增一个 `PublicationService.cs`，集中处理发布候选、重组校验、格式转换、PNG 元数据与 ZIP，避免把同一发布规则拆成多层包装。
- `Program.cs` 只注册服务与两个发布接口；前端只替换现有发布占位页。
- 新增阶段 5 自检，覆盖选择快照、无模型安全回退、重组完整性、世界书键、正则结构、PNG 元数据和 ZIP 文件清单。

## 验收

1. 未选择产物、选中版本已变化、必需输出缺失或 PNG 无效时给出明确错误。
2. 重组候选不能重复、遗漏或编造 blockId；修正仍失败时安全补齐并在发布结果中明确标注。
3. 所有选中产物版本在最终世界书映射中恰好出现一次；合法 wrap/rename 后仍保持完整覆盖，附属世界书正文不进入包。
4. 角色卡 JSON、世界书 JSON、正则 JSON 均可重新解析，PNG 可读出与 JSON 同源的角色数据。
5. Release 仍发布为单个自包含 `A.U.T.O.exe`，不新增第三方依赖。
