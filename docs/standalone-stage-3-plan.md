# A.U.T.O 独立版阶段 3 实施计划

## Task Envelope

- **目标**：让每个步骤保存多个可命名对话，并完整迁移脚本版已有的消息操作、重试和滚动规则。
- **已有证据**：脚本基线 `0.6.41` 已实现多对话、消息编辑删除、最新输入重试、逐条回顶和流式滚动主权；独立版阶段 2 已形成单对话生成闭环。
- **允许动作**：升级独立版步骤文件 Schema、增加兼容迁移、增加步骤/对话/消息接口并调整独立版界面。
- **禁止动作**：不修改脚本版；不提前实现产物提取、附属世界书、发布或其他预设；不读取用户现有 API 密钥。
- **预期产物**：可运行的多对话闭环、自检与浏览器验收、阶段记录和单文件发布包。
- **完成标准**：多项目/步骤/对话不串写；旧单对话文件无损迁移；失败和 revision 冲突不覆盖消息；保存重开一致。

## 数据与命令契约

### 步骤权威状态

每个 `steps/NN.json` 升级为：

- `revision`：该步骤全部对话共享的 CAS 版本。
- `activeConversationId`：当前对话稳定 ID。
- `conversations[]`：名称、创建/更新时间和消息数组。
- `status`：任一对话有消息时至少为 `draft`；全部为空时为 `idle`。

阶段 2 的顶层 `turns[]` 只作为旧格式输入。首次读取时映射到一个名为“默认对话”的会话，下一次写入时保存为新格式；原文件仍由 `.previous` 保留一份有效版本。

### 用户动作

| 动作 | 成功结果 | 失败语义 |
|---|---|---|
| 新建对话 | 建立空对话并立即激活 | revision 变化则拒绝并刷新 |
| 切换对话 | 只改变当前步骤的激活 ID | 生成期间前端禁止；旧页面写入被 CAS 拒绝 |
| 重命名 | 更新名称与步骤 revision | 空名称拒绝，不修改文件 |
| 删除对话 | 删除后激活相邻对话 | 最后一个拒绝删除，提示改用清空 |
| 清空对话 | 仅清空当前对话 | 其他对话与未来产物库不受影响 |
| 编辑/删除消息 | 按稳定消息 ID 原子修改 | 找不到消息或 revision 冲突时不写入 |
| 重试最新输入 | 成功时用新回复替换该输入后的旧回复 | 请求失败保留旧回复；非最新输入拒绝 |

## 生成归属与滚动规则

- 生成请求固定 `projectId + stepNumber + conversationId + expectedStepRevision`。
- 普通生成先提交用户消息，再调用模型；用户消息立即以乐观层显示，保存失败时撤销。
- 重试不提前删除旧回复；模型成功或停止且有部分正文时再原子替换尾部，失败时旧回复原样保留。
- 流式正文仅更新当前草稿节点；用户向上滚动后立即停止自动跟随，自己回到底部或点击“回底”后恢复。
- “回顶”从当前定位连续跳到上一条消息顶部；“回底”始终定位最新消息底部。

## 本阶段边界

- 不建立正式产物与版本历史；对话操作的“产物不受影响”在本阶段表现为不触碰任何未来产物文件。
- 提示词预览纳入本阶段，并与真实发送复用同一装配函数；HTML 沙箱预览和对话搜索导出仍留在后续阶段。
- 不改变阶段 2 的模型渠道与凭据结构。

## 验证矩阵

1. 旧 `turns[]` 文件迁移后消息、顺序和角色不变。
2. 同一步骤创建两个对话，分别写入消息，切换和重开后不串写。
3. 重命名、删除非最后对话、最后对话删除拒绝、清空均符合规则。
4. 用户与 AI 消息可编辑/删除，空编辑和旧 revision 不污染资料。
5. 重试成功替换旧尾部，模型失败保留旧尾部。
6. 生成期间项目、步骤、对话切换锁定；后端仍以 conversation ID 与 revision 防迟到写入。
7. 手动上滚后流式 chunk 不拉回；回顶可连续点击；回底恢复跟随。
8. Debug、自检、浏览器、保存重开和单文件发布分别记录证据等级。
