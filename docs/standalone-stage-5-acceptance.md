# 独立版迁移阶段 5 验收记录

## 结论

阶段 5 的发布交付闭环已经实现：用户可在发布页填写角色卡信息、选择当前正式产物版本、附加可选 PNG 头像与 Step 24 通用正则，然后下载完整 ZIP。发布会优先调用 A.U.T.O 隐藏重组提示词，模型回复只作为候选；候选必须通过严格覆盖校验，失败自动修正一次，两次仍不可用时使用有明确提示的本地安全分组，保证已选世界书产物不被静默遗漏。

脚本版没有修改。附属世界书仍只参与 AI 参考，没有进入发布接口或测试包。

## 已实现范围

| 能力 | 结果 |
|---|---|
| 发布选择快照 | 只接受当前产物库中仍被选中的版本 ID；revision 或版本已变化时拒绝旧请求 |
| AI 自动重组 | 读取完整预设中的隐藏重组条目与本次结构报告，不写入普通步骤对话 |
| 候选校验 | 校验源世界书、mapping、blockId 唯一覆盖、动作类型、枚举、关键词、位置、顺序与条目属性 |
| 自动修正与回退 | 无效候选只修正一次；仍失败时按原交付目标完整分组并把提示写入创作档案 |
| 缓存 | 只在产物身份、当前版本和交付位置签名一致时复用；正文原地编辑沿用分组，增删或切换版本失效 |
| 世界书 | 同时生成独立 `entries` 对象格式与角色卡内嵌 `entries` 数组格式 |
| 正则 | Step 23 状态栏与 Step 24 九条通用正则转为 SillyTavern 实际保存的 camelCase 局部正则格式 |
| 角色卡 | 生成 `chara_card_v3` / `3.0` JSON，包含内嵌世界书、局部正则、开场与创作者说明 |
| PNG | 仅接受结构和 CRC 有效的 PNG；移除旧 `chara`/`ccv3` 后写入同源的两个元数据块 |
| ZIP | 内存中完成全部文件、覆盖和格式复核后才返回下载，不产生半成品 |

## ZIP 文件清单

- `角色名.character.json`

- `角色名.regex.json`
- `角色名-创作档案.md`
- `角色名.png`（仅在提供有效 PNG 头像时）

## 兼容决策

- 角色卡与 PNG 以本地 SillyTavern 1.18.0 源码为权威：PNG 同时写 `chara` 和 `ccv3`，读取时 `ccv3` 优先。
- 正则备份与角色卡内部均使用当前 SillyTavern 的 `scriptName`、`findRegex`、`placement` 等字段；不把酒馆助手公开接口的 snake_case 结构直接写进卡片。
- 世界书默认递归字段暂时保持脚本版行为，不在首次完整移植阶段主动改变运行语义。

## 尚未宣称

- 未使用用户真实模型密钥；AI 重组协议由可控模型响应验证，真实供应商差异留到最终全量验收。
- 本轮用 SillyTavern 自带校验器验证了实际导出 JSON，但没有把测试卡写入用户正在使用的酒馆资料目录，也没有宣称完成酒馆 UI 中的 JSON/PNG 人工导入回放。
- 阶段 6 的新手引导、更新器、备份恢复、诊断、全量清理、移动端发布入口与最终便携包验收尚未开始。
