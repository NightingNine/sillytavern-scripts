# A.U.T.O 独立创作台：讨论与决定记录

## 当前结论

### Task Envelope

- 目标：把现有 A.U.T.O 角色卡创作台迁移为完全脱离 SillyTavern 的本地独立网页版。
- 用户入口：运行本地启动程序后，自动在浏览器中打开创作台。
- 保留项：现有 SillyTavern 脚本继续独立维护，不被独立版替换或破坏。
- 开发隔离：独立版使用 `feature/auto-card-studio-standalone` 分支和单独工作目录。
- 当前允许动作：建立隔离分支、盘点依赖、讨论和编写完整设计。
- 当前禁止动作：在完整设计确认前重写现有脚本核心、迁移正式项目数据或发布独立安装包。
- 预期产物：独立网页版、轻量本地服务、一键启动入口，以及项目/预设/世界书/角色卡的导入导出能力。
- 完成标准：不启动 SillyTavern 也能完成项目创建、AI 生成、对话与产物管理、保存重开和角色卡交付。

### Route Decision

- 入口：已有应用迁移。
- 当前阶段：需求讨论与宿主边界确认。
- 迁移原则：先建立现有行为与依赖清单，再按可运行切片迁移；脚本版和独立版不共享运行时状态。
- 推荐宿主：HTML/CSS/JavaScript 前端 + 本机轻量服务；浏览器只负责界面，本地服务负责模型请求、密钥和文件。

### Gate State

- 总体方向：已确定——完全脱离 SillyTavern。
- 运行形态：已确定——启动本地程序后在浏览器打开。
- 启动与分发：已确定——提供无需安装的便携式一键启动程序，双击后自动启动本地服务并打开浏览器。
- 保留脚本版：已确定。
- 完整设计：待讨论、待用户确认。
- 正式实施：尚未进入。
- 验收与发布：尚未进入。

### 待讨论

1. 模型连接与 API 密钥保存方式。
2. 本地项目、资源库和旧项目迁移方式。
3. 预设、世界书与角色卡的兼容范围。
4. 独立版与脚本版未来如何分别更新。

## 讨论记录

### 决定 001：是否完全脱离 SillyTavern

- 作用：决定独立版是否继续依赖酒馆页面、插件和全局接口。
- 用户选择：完全脱离。
- 结论状态：已确定。
- 影响：模型调用、存储、预设、世界书、角色卡导出和更新能力都需要由独立应用自行承担。

### 决定 002：独立版的基本运行形态

- 方案：本地独立网页版，由启动程序启动轻量服务并自动打开浏览器。
- 用户选择：采用该方案。
- 结论状态：已确定。
- 影响：界面仍使用 Web 技术，但不采用受跨域和密钥限制较大的单文件 HTML 方案。

### 决定 003：现有脚本如何处理

- 用户要求：另建分支开发，当前脚本必须保留。
- 结论状态：已确定。
- 落地：建立 `feature/auto-card-studio-standalone` 分支及单独工作目录；后续独立版新增文件，不直接替换脚本版入口。

### 决定 004：最终启动与分发形式

- 作用：决定普通用户是否需要安装软件或准备开发环境。
- 方案：提供便携式一键启动程序；双击 `.exe` 后启动本地服务并自动打开默认浏览器。
- 用户选择：采用该方案。
- 结论状态：已确定。
- 影响：最终发布包无需安装，也不要求用户预装 Node.js；程序关闭时应一并结束自身启动的本地服务，项目数据与程序文件分开保存。
