# A.U.T.O 独立创作台：讨论与决定记录

## 当前结论

### Task Envelope

- 目标：先把当前正式脚本版 A.U.T.O 角色卡创作台的全部功能完整迁移为完全脱离 SillyTavern 的本地独立网页版。
- 用户入口：运行本地启动程序后，自动在浏览器中打开创作台。
- 保留项：现有 SillyTavern 脚本继续独立维护，不被独立版替换或破坏。
- 开发隔离：独立版使用 `feature/auto-card-studio-standalone` 分支和单独工作目录。
- 当前允许动作：建立隔离分支、以当前正式脚本为行为基线盘点全部功能与依赖、讨论和编写完整设计。
- 当前禁止动作：在完整设计确认前重写现有脚本核心、迁移正式项目数据或发布独立安装包。
- 预期产物：脚本版功能完整对等的独立网页版、轻量本地服务、一键启动入口，以及项目/预设/世界书/角色卡的导入导出能力。
- 完成标准：不启动 SillyTavern 也能完成脚本版现有的全部用户流程；逐项功能对照与回归验收通过后，才讨论其他预设和新增能力。

### Route Decision

- 入口：已有应用迁移。
- 当前阶段：正式脚本行为基线审计与宿主替换设计。
- 迁移原则：先建立现有行为与依赖清单，再按可运行切片迁移；脚本版和独立版不共享运行时状态。
- 推荐宿主：HTML/CSS/JavaScript 前端 + 本机轻量服务；浏览器只负责界面，本地服务负责模型请求、密钥和文件。

### Gate State

- 总体方向：已确定——完全脱离 SillyTavern。
- 运行形态：已确定——启动本地程序后在浏览器打开。
- 启动与分发：已确定——提供无需安装的便携式一键启动程序，双击后自动启动本地服务并打开浏览器。
- API 密钥：已确定——使用当前 Windows 用户的系统安全凭据库保存，不进入项目、导出包、程序目录或版本库。
- 项目数据：已确定——统一保存在便携程序旁的 `data` 文件夹，可随整个程序目录一起迁移。
- 自动备份：已确定——重要写入保留上一份有效文件，每天生成一份完整备份并保留最近 7 份，同时支持手动立即备份和确认后恢复。
- 模型接口：已确定——首版支持 OpenAI 兼容接口，并原生支持 Anthropic Claude 与 Google Gemini；连接配置全局复用，密钥仍由 Windows 凭据管理器保存。
- 旧项目迁移：已确定——不修改脚本版，独立版批量导入脚本现有的 `.auto-card-studio.json` 项目文件，导入前预览且不覆盖现有资料。
- 第一阶段范围：已确定——完整移植当前正式脚本的全部功能；其他预设与新增能力推迟到功能对等验收之后。
- 保留脚本版：已确定。
- 完整设计：待讨论、待用户确认。
- 正式实施：尚未进入。
- 验收与发布：尚未进入。

### 待讨论

1. 完成正式脚本的逐项功能、数据和 SillyTavern 宿主依赖盘点。
2. 确认每项宿主依赖在独立版中的结果等价替代方式。
3. 独立版与脚本版未来如何分别更新（功能对等后再讨论）。

## 讨论记录

### 决定 001：是否完全脱离 SillyTavern

- 作用：决定独立版是否继续依赖酒馆页面、插件和全局接口。
- 用户选择：完全脱离。
- 结论状态：已确定。
- 影响：模型调用、存储、预设、世界书、角色卡导出和更新能力都需要由独立应用自行承担。

### 决定 002：独立版的基本运行形态

- 方案：本地独立网页版，由启动程序启动轻量服务并自动打开浏览器。
- 用户选择：采用该方案。
- 结论状态：已确定。
- 影响：界面仍使用 Web 技术，但不采用受跨域和密钥限制较大的单文件 HTML 方案。

### 决定 003：现有脚本如何处理

- 用户要求：另建分支开发，当前脚本必须保留。
- 结论状态：已确定。
- 落地：建立 `feature/auto-card-studio-standalone` 分支及单独工作目录；后续独立版新增文件，不直接替换脚本版入口。

### 决定 004：最终启动与分发形式

- 作用：决定普通用户是否需要安装软件或准备开发环境。
- 方案：提供便携式一键启动程序；双击 `.exe` 后启动本地服务并自动打开默认浏览器。
- 用户选择：采用该方案。
- 结论状态：已确定。
- 影响：最终发布包无需安装，也不要求用户预装 Node.js；程序关闭时应一并结束自身启动的本地服务，项目数据与程序文件分开保存。

### 决定 005：API 密钥保存方式

- 作用：决定模型密钥能否被长期记住，以及是否会随项目或便携程序泄漏。
- 方案：使用 Windows 系统安全凭据库，由本地服务读取，浏览器前端只显示是否已配置和脱敏后的标识。
- 用户选择：采用该方案。
- 结论状态：已确定。
- 影响：密钥不会写入项目、导出文件、日志、程序目录或 Git 仓库；便携程序移动到另一台电脑或切换 Windows 用户后需要重新填写，并提供替换与删除密钥的入口。

### 决定 006：项目资料存放位置

- 作用：决定项目、对话、产物、预设和资源库能否与便携程序一起移动。
- 方案：在程序同级目录使用统一的 `data` 文件夹保存全部非密钥资料。
- 用户选择：采用该方案。
- 结论状态：已确定。
- 影响：复制整个程序目录即可迁移资料；程序升级不得覆盖 `data`，启动时需检查目录写入权限和剩余空间。误删或损坏程序目录会同时影响资料，因此必须另行确定自动备份与恢复策略。

### 决定 007：自动备份与恢复

- 作用：保护随便携程序一起存放的项目资料，并让误操作或文件损坏能够恢复。
- 方案：
  - 项目、预设、附属世界书等重要资料写入时采用安全替换，并保留上一份通过校验的有效文件。
  - 每天首次发生资料变更时，在 `data/backups` 生成一份完整备份，只保留最近 7 份。
  - 设置页提供“立即备份”，方便在升级、搬移或批量修改前主动留档。
  - 恢复前显示备份日期和影响范围，并先保护当前资料；未经用户确认不覆盖现有数据。
- 用户选择：采用推荐方案。
- 结论状态：已确定。

### 决定 008：首版模型接口与连接配置

- 作用：决定独立版可以直接连接哪些模型服务，以及不同项目如何复用连接。
- 推荐方案：以覆盖面较广的 OpenAI 兼容接口为主，同时为协议差异明显的 Anthropic Claude 和 Google Gemini 提供原生适配。
- 用户选择：采用推荐方案。
- 结论状态：已确定。
- 首版范围：
  - 支持 OpenAI 兼容接口，可填写服务地址、模型名称和常用生成参数，覆盖 OpenAI、OpenRouter、DeepSeek、常见中转服务及兼容的本地模型服务。
  - 支持 Anthropic Claude 原生接口和 Google Gemini 原生接口，不要求用户额外配置中转。
  - 支持保存多套全局连接配置、测试连接，并在服务允许时获取模型列表；所有项目可以复用这些连接。
  - 支持流式与非流式生成、主动停止、连接与生成超时，以及可理解的鉴权、限流、网络、上下文超限和响应截断提示。
  - 普通配置保存在 `data` 中；API 密钥只保存于 Windows 凭据管理器，项目和导出包只引用连接配置，不复制密钥。
- 明确边界：首版不照搬 SillyTavern 的全部模型后端；其他协议根据实际需求后续增加适配器，避免首版承担不必要的维护成本。

### 决定 009：现有脚本版项目迁移

- 作用：决定用户如何把脚本版中已经创作的项目安全带入独立版。
- 已有证据：脚本版当前能够导出 `.auto-card-studio.json`，其中包含项目、分步骤对话、产物保险库以及该项目引用的附属世界书快照。
- 用户修正：脚本版不需要改动，因此不增加“导出全部项目迁移包”等新功能。
- 采用方案：
  - 独立版提供旧项目迁移入口，可一次选择多个现有 `.auto-card-studio.json` 文件并批量解析。
  - 正式写入前展示可导入项目、包含资料、格式版本、重复项和异常项，由用户确认后继续。
  - 每个项目作为新副本导入；ID 或名称重复时生成新 ID 并自动改名，不覆盖独立版已有项目。
  - 原始导入文件按来源留存，转换在副本上进行；单个文件失败不影响其他已通过校验的项目。
  - API 密钥和浏览器内部状态不迁移；独立版不直接读取脚本版的 IndexedDB 或 localStorage。
- 推荐理由：完全沿用脚本已有的公开导出能力，不让迁移依赖特定浏览器、酒馆地址、登录状态或新增脚本功能。
- 结论状态：已确定。

### 决定 010：第一阶段只做脚本版完整移植

- 作用：确定独立版第一阶段的唯一功能基线，避免在迁移尚未完成时同时扩展通用预设能力而稀释目标。
- 用户要求：首先完全实现脚本版的所有功能，完成后再讨论其他预设和新增能力。
- 采用原则：
  - 当前正式脚本及其已经发布的用户可见行为、数据规则和异常处理是第一阶段的权威基线。
  - 界面、项目与多对话、AI 生成、提示词装配、正则处理、产物、自建产物、附属世界书、设置、发布、备份、响应式布局和新手引导等均纳入逐项盘点，不能只迁移主流程。
  - 依赖 SillyTavern 的技术调用必须替换为独立宿主能力；保持用户取得的结果等价，不保留对 SillyTavern 页面、插件或全局对象的运行依赖。
  - 不借迁移改变已经确认的交互和业务规则；确需因独立宿主改变入口时，必须在功能对照中明确记录替换关系和验收方式。
  - 其他预设的通用导入、条目分类和工作台方案扩展暂缓，不属于第一阶段实现范围。
- 结论状态：已确定。
