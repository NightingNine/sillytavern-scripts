## 2. 目标与非目标

### 目标

- 双击一个便携式 `.exe`，自动启动仅限本机访问的服务并在默认浏览器打开创作台。
- 不启动 SillyTavern，也能完成脚本版全部项目、生成、对话、产物、资源、发布和恢复流程。
- 保留现有界面风格、29 步工作流、九组分类、移动端规则以及已经修复的交互细节。
- 非敏感资料存入程序旁 `data` 文件夹；密钥存入 Windows 凭据管理器。
- 最终交付 SillyTavern 可导入的角色卡 ZIP 包。

### 非目标

- 第一阶段不支持其他预设自动转换为新工作台方案。
- 不修改、替换或要求升级现有脚本版。
- 不直接控制 SillyTavern、不读取其页面状态、不扫描其数据目录。
- 不增加云同步、账号系统、多人协作、插件市场或跨平台发行。

## 3. 总体结构

```text
用户双击 A.U.T.O.exe
→ 本地服务锁定单实例并检查 data
→ 生成本次会话令牌，只监听 127.0.0.1
→ 打开默认浏览器
→ 浏览器加载原生前端
→ 前端通过本地 API 读取项目快照
→ 用户操作形成带 expectedRevision 的命令
→ 本地服务校验并安全写入 data
```

生成链：

```text
当前项目快照
→ 预设条目与正则状态
→ 当前对话、正式产物、后序开关、附属世界书命中
→ 宏保护与消息队列装配
→ Token 预算校验与提示词预览
→ 本地模型网关
→ 流式草稿
→ 完整响应
→ 正则后处理与产物候选提取
→ 用户可见对话 + 独立产物库安全保存
```

## 4. 前端设计

- 直接迁移当前脚本的 HTML、CSS 和已确认交互，不重新设计工作台。
- 把现有单文件脚本按实际职责拆成少量 ES Modules：工作区、项目/对话、Prompt/正则、产物/资源、发布、API 客户端。
- 不引入通用状态框架；服务端项目快照是正式数据源，前端只持有当前 revision 的编辑视图和流式草稿。
- 自动保存携带 `expectedRevision`。发生冲突时停止覆盖，提示重新载入或导出当前草稿。
- HTML 代码预览继续使用无脚本权限的沙箱 iframe。
- 导入正则在受限 Worker 中执行；超时或异常时终止本次处理并保留原始模型回复。

## 5. 本地服务设计

- 使用 .NET 10 Minimal API，绑定 `127.0.0.1` 的可用端口，不监听局域网。
- 启动 URL 携带一次性令牌，交换为仅本机、HttpOnly、SameSite 严格会话；写请求校验来源与防跨站令牌。
- 重复启动时复用已有实例并重新打开页面；页面中的“关闭”请求安全保存后结束服务，异常关闭后服务在无活动任务时自动退出。
- 服务职责仅包括静态页面、存储、凭据、模型网络、文件导入导出、打包、备份、更新和诊断，不复制前端 A.U.T.O 业务规则。

## 6. 数据结构与保存

```text
data/
  app-settings.json
  connections.json                 # 只保存凭据引用，不保存密钥
  resources/
    preset.json
    regex.json
    reference-worldbooks/*.json
  projects/<projectId>/
    project.json                    # 名称、当前步骤、项目级设置、revision
    steps/01.json ... 29.json       # 多对话与消息
    artifacts.json                  # 正式产物、版本、选择和上下文开关
  imports/originals/                # 导入原件与来源摘要
  backups/                          # 最近 7 份每日备份
  logs/                             # 脱敏诊断
```

- 写入采用“临时文件 → 解析与校验 → 替换 → 读回确认”，保留上一份有效文件。
- 项目级 revision 防止旧页面和迟到请求覆盖新内容；模型保存失败只重试写入，不重新调用模型。
- 每天第一次重要写入前生成完整备份，设置页支持立即备份和恢复预览。
- 导入项目、预设、正则和世界书时保存原件哈希；转换失败不改动现有资料。

## 7. 模型与连接

- 首版适配 OpenAI 兼容接口、Anthropic Claude 和 Google Gemini。
- 所有项目共用连接预设；地址、模型和参数写入 `data`，API 密钥写入 Windows 凭据管理器。
- 模型网关统一流式事件、取消、超时、鉴权、限流、网络、上下文超限、截断和上游错误。
- 流式片段只更新临时草稿；完整结束后才执行正则、提取产物并保存。
- 用户上滚后停止自动跟随；主动回到底部或点击“回底”后恢复跟随。

## 8. Prompt、宏、正则和 Token

- 第一阶段只实现当前 A.U.T.O 预设实际使用的条目顺序、参数与宏行为，不扩展通用预设解释器。
- 固定同一项目 revision 后依次选择：启用预设条目、当前会话、正式产物、后序产物、实际激活附属世界书、本轮输入。
- `{{char}}`、`{{user}}` 及基线已使用宏按当前脚本时机处理；未知宏保留原文并在提示词预览中警告。
- 预设自带正则和独立正则按启用顺序处理；不执行 JavaScript、EJS、MVU 或其他插件代码。
- Token 支持模型已知时使用匹配 tokenizer；未知时显示 `≈` 保守估算。输入加最大回复超过配置上限时阻止请求，不静默截断正式产物。
- 提示词预览与真正发送使用同一装配结果，并记录不含正文的来源、顺序、Token 和指纹诊断。

## 9. 产物与附属世界书

- 对话与产物继续完全解耦；消息编辑、删除、重试、清空和切换对话不修改正式产物库。
- 产物身份、集合型标签、版本选择、手动加入、自建产物、上下文开关、分类和搜索保持基线规则。
- 附属世界书进入全局本地资料库，每项目独立选择整本和条目。
- 常驻条目每轮发送；关键词条目只扫描本轮用户输入。选择在请求开始前固定，流式期间不重新命中。
- 附属世界书只参与 AI 参考，不进入产物、重组或最终角色卡。

## 10. 发布与角色卡包

- 发布前由用户勾选正式产物；隐藏重组步骤只读取本次选择和现有条目计划。
- 保留 AI 重组、完整性检查、修正一次和本地安全补全规则，任何已选产物不得静默丢失。
- Step 23 继续生成状态栏局部正则；Step 24 继续分别确认通用正则和角色卡交付。
- 下载 ZIP 内容：
  - `角色名.character.json`：始终生成，包含角色、嵌入世界书和局部正则。
  - `角色名.png`：提供有效 PNG 头像时生成，并嵌入同一角色数据。
  - `角色名.worldbook.json`：独立世界书备份。
  - `角色名.regex.json`：独立局部正则备份。
  - `角色名-创作档案.md`：可读档案。
- 打包前重新解析并校验 JSON、产物覆盖和 PNG 结构；失败时不下载半成品。

## 11. 更新、恢复与隐私

- 更新检查只发送当前应用版本，不发送项目、提示词或密钥。
- 下载的新程序必须校验版本与哈希；替换前备份当前程序和 `data`，失败恢复旧程序。
- 日志默认只记录版本、ID、耗时、HTTP 状态、标准错误码和内容指纹，不记录完整 Prompt、回复、用户输入或 API 密钥。
- 设置页提供项目导出、数据备份、日志查看/删除、密钥替换/删除和全量数据清理。

## 12. 主要风险与验证

| 风险 | 影响 | 处理与证据要求 |
|---|---|---|
| 现有脚本是大型单文件 | 移植时可能遗漏隐式状态 | 以功能对等表逐项追踪，不一次重写全部逻辑 |
| 三种供应商流式协议不同 | 取消、截断或错误处理不一致 | 使用可控假服务后分别进行真实接口验证 |
| 导入正则可能耗时或恶意 | 页面冻结 | Worker 隔离、输入上限、超时终止、保留原始响应 |
| 文件写入中断 | 项目损坏 | 原子替换、读回、上一份有效文件和恢复演练 |
| 角色卡 PNG 格式差异 | SillyTavern 无法导入 | JSON 必有；PNG 使用真实 SillyTavern 回放验证 |
| 自动更新覆盖程序 | 无法启动或资料损坏 | 分阶段替换、哈希校验、保留旧程序和独立数据备份 |

## 13. 全局验收标准

- 功能对等审计中的所有必需项达到“已验证”。
- 旧项目文件可批量导入，保存重开后项目、对话、产物版本与资源状态一致。
- 三类模型接口至少完成连接、生成、流式、停止、错误和超限测试；未获得真实密钥的渠道明确标记未验证。
- 生成期间手动上滚不被拉回，编辑消息尺寸正确，多对话不串写，产物不被对话操作污染。
- 常驻与关键词附属世界书正反命中正确，提示词预览与实际发送一致。
- 角色卡 JSON 能被 SillyTavern 导入；有头像时 PNG 同样可导入，世界书与正则完整。
- 自包含 `.exe` 在未安装开发环境的 Windows 测试环境中启动、保存、重开、备份和恢复成功。
