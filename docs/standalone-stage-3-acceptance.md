# A.U.T.O 独立版阶段 3 验收记录

## 结论

阶段 3 已实现并完成本地协议、自检与真实浏览器行为验收。每个步骤可以保存多个独立命名对话；消息操作、最新输入重试、提示词预览、字体设置与滚动主权已经接通。脚本版仍保持冻结，未被本阶段修改。

本结论不等于“真实外部模型已通过”：浏览器生成使用独立版本机显式开启的 Mock OpenAI 兼容端点，未读取或调用用户现有 API 密钥。

## 自动自检

`dotnet run --project standalone/AutoCardStudio.Host/AutoCardStudio.Host.csproj -c Debug -- --self-test` 通过：

- 阶段 2 顶层 `turns[]` 无损迁移到稳定 ID 的“默认对话”，新格式保存后仍保留上一份有效文件。
- 同一步骤的两个对话分别保存消息，切换、重开后不串写。
- 创建、激活、重命名、删除非最后对话、拒绝删除最后对话和清空通过。
- 用户/AI 消息按稳定 ID 编辑或删除；旧 revision 被 CAS 拒绝。
- 最新用户输入重试成功时原子替换旧尾部，消息数量不重复增长。

## 浏览器行为证据

在隔离进程、隔离临时 `data` 和本地 Mock 模型中完成：

- 普通生成后立即出现用户消息，流式结束后保存 AI 回复。
- 创建“验收分支”后自动切换；重命名为“备用方案”；切回默认对话时原两条消息完整恢复。
- 用户消息编辑框保持原消息卡片宽度，初始高度不小于原正文，字体与对话设置一致；保存后稳定恢复阅读态。
- 最新输入重试前后用户消息 ID 不变、AI 回复 ID 更新，旧回复没有残留或重复。
- 提示词预览展示实际 6 条消息、来源角色、名称、内容与估算 Token；最后一条是当前本轮输入。
- 对话字体从默认 15 px 调至上限 20 px 后，消息正文同步为 20 px。
- 长消息场景下，发送前已上滚时生成后 `scrollTop` 保持不变；生成期间上滚后，后续分片和完成事件也未拉回底部。
- 连续两次“回顶”分别向上定位不同消息；“回底”定位最新消息底部。
- 页面控制台无 error 级日志。

## 清理与回退

- 浏览器验收使用临时互斥标识、临时运行目录和临时 `data`，没有关闭验收前已存在的独立版进程。
- 临时连接已通过正式删除接口移除，因此 Windows 凭据中的测试密钥同步删除。
- 两个临时服务均已正常关闭，临时数据与运行目录均已删除。
- 发布残留清理时发现一个验收前已从 `standalone/publish/stage2` 启动的旧程序；该进程与锁定的旧 EXE 被保留，但其未受 Git 管理的阶段 2 测试 `data` 子目录被清理，无法从仓库直接恢复。脚本版与新的阶段 3 临时/正式资料未使用该目录。
- 数据迁移保留 `.previous`，旧页面写入由步骤 revision 拒绝；若需要回退代码，可回到阶段 2 提交并恢复旧有效步骤文件。
