# A.U.T.O 独立版阶段 2 实施计划

## 阶段目标

形成一次真实生成闭环：用户导入完整 A.U.T.O v2.0 预设，建立一套全局模型连接，在任一步骤发送输入，立即看到自己的消息，再看到流式或完整 AI 回复；停止、失败和重开后数据归属保持正确。

## 当前切片边界

### 本阶段实现

- 导入 A.U.T.O 预设 JSON，只采用最长 `prompt_order` 实际引用的条目，并验证 29 个步骤与重组条目齐全。
- 同步预设内置 `extensions.regex_scripts`，也支持单独导入正则 JSON；原始文件、文件名与 SHA-256 保留在 `data/imports`。
- 所有项目共用模型连接；支持 OpenAI 兼容、Anthropic Claude 与 Google Gemini 三种协议。
- 普通连接字段写入 `data/settings/connections.json`；API 密钥只写入 Windows 凭据管理器。
- 支持获取模型、流式/非流式生成、停止、超时、标准错误提示和脱敏诊断。
- 当前步骤采用一个默认对话保存用户消息与 AI 回复；完整多对话管理留到阶段 3。
- 生成前固定项目、步骤、step revision、预设版本和连接版本；上下文超限时不写入用户消息。

### 本阶段不实现

- 不提取正式产物，不建立产物版本历史。
- 不发送附属世界书或正式产物上下文。
- 不实现多对话命名、编辑、删除、重试和步骤确认。
- 不支持把其他预设转换成创作流程。

## 权威状态与失败语义

| 数据 | Owner | 保存位置 | 失败结果 |
|---|---|---|---|
| 预设与正则 | `ResourceStore` | `data/resources` 与只读导入原件 | 校验失败不替换当前资源 |
| 连接普通字段 | `ConnectionStore` | `data/settings/connections.json` | revision 冲突拒绝覆盖 |
| API 密钥 | `WindowsCredentialVault` | 当前 Windows 用户凭据库 | 保存失败不谎称“已配置” |
| 当前步骤消息 | `ProjectStore` | `data/projects/{id}/steps/NN.json` | step revision 冲突拒绝串写 |
| 流式正文 | 浏览器临时草稿 | 不作为正式存档 | 完成后提交；主动停止可保存已收到部分 |

## Prompt 与模型契约

1. 预设顺序严格来自导入文件的有效 `prompt_order`。
2. 占位条目不直接发送；29 个步骤中只发送当前步骤条目，非步骤辅助条目遵守启用状态。
3. 追加模板变量保护、项目母题/当前步骤、当前默认对话与本轮输入。
4. `{{char}}` 与 `{{user}}` 原样保留；阶段 2 不执行 EJS、MVU、脚本或未知宏。
5. chunk 只更新流式草稿；收到完整响应后才写入 AI 消息。失败不写入伪造回复。
6. 日志只记录请求 ID、模型、阶段、耗时、HTTP 状态和正文指纹，不记录 Prompt、回复或密钥。

## 验收门

- 结构：发布包和前端均不包含密钥；宿主不引用 SillyTavern 运行时。
- Mock：三种协议至少覆盖一个成功响应；OpenAI 兼容覆盖流式、非流式、取消和错误。
- 浏览器：导入资源、保存连接、发送消息、即时显示、流式完成、停止与重开恢复。
- 持久化：预设、连接引用和步骤消息重开一致；错误或冲突不污染旧 revision。
- 发布：仍保持一个自包含 `A.U.T.O.exe`，没有新增运行时依赖。

阶段 2 全部通过前，不进入多对话和产物提取。
